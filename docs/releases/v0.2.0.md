## Upgrading from v0.1.0

v0.2.0 measures code that v0.1.0 did not, so an existing baseline will be
short of entries. After installing, in each repo:

```sh
$EDITOR qgate.toml                # qgate_version = "0.2.0"
qgate baseline create --force     # re-measure with v0.2.0
git add qgate.toml qgate.baseline
qgate approve                     # the version bump and any new entries need approval
```

**Elixir repos must re-baseline.** `.ex` and `.exs` files now get function
length entries (each `def`, `defp`, `defmacro`, `defguard` clause and ExUnit
`test`), and their duplicate blocks are found with the Elixir grammar instead
of the generic tokenizer, so duplicate keys change. Without re-baselining,
the first commit that touches an Elixir file fails on violations that were
already there.

Go repos with `// Code generated ... DO NOT EDIT.` files should re-baseline
too: those files are now skipped, so `qgate baseline prune` will drop their
entries.

## Elixir

- Function length for Elixir with tree-sitter-elixir. Entries are keyed like
  `Elara.Math::add#0` (one per clause), `Elara.Math::String.Chars.Elara.Math::to_string#0`
  inside `defimpl ... for:`, and `Elara.MathTest::add/2::adds two numbers#0`
  for an ExUnit `test` inside `describe`. A computed name such as
  `def unquote(name)()` is measured as `<dynamic>` rather than skipped.
- `format = "mix"` parses `mix compile` diagnostics (Elixir 1.15+ and older
  layouts), ExUnit failures and `mix format --check-formatted`. With
  `--warnings-as-errors`, warnings that failed the build are errors. Credo
  reports through `--format sarif`. ANSI colour codes are stripped from all
  tool output before parsing.
- `qgate install` in a Mix project writes a starter config with `mix format`,
  `mix compile --warnings-as-errors`, `mix credo --strict` (when `.credo.exs`
  exists) and `mix test`.
- Guarded without approval: `mix.exs` aliases, `cli`, and the `project` keys
  that change what is compiled, tested or covered (dependency bumps don't
  count); `.formatter.exs`, `.credo.exs`, `.dialyzer_ignore.exs`,
  `coveralls.json` and `test_helper.exs`; and new `credo:disable`,
  `@dialyzer`, `coveralls-ignore`, `@tag :skip`, `@moduletag :skip`,
  `@describetag :skip` and `@compile {:no_warn_undefined, ...}` markers.
- `priv/static/assets/` is excluded by default.

## Go

- Files with a `// Code generated ... DO NOT EDIT.` header are skipped by the
  length and duplication checks, as golangci-lint does. Adding such a file, or
  adding the header to an existing one, needs approval.

## Approvals and the ratchet

- Signed, committed approvals: `qgate approve --base <ref> --sign` writes a
  signature under `.qgate/approvals/` that CI verifies against
  `[approvals] allowed_signers`, so a loosening can be approved for CI and
  remote sessions. A change can never trust its own key.
- `[ratchet] headroom_lines` lets a baselined function or file grow a few
  lines past its recorded size without approval. It does not add up across
  changes, and raising it needs approval.

## CI and config

- `qgate run --stage push --base <ref>` checks a branch against its merge base,
  and `--format github` prints workflow annotations and a step summary.
- `fixtures` globs, `[[package]] glob = ...` limits and `attribute_macros` for
  C/C++.

## Fixes

- A tool that exits non-zero always fails the run. v0.1.0 could report a
  failing tool as passing when its only parsed findings were warnings in
  dependencies.
- A tool that fails with no output now says so and suggests how to make it
  print what failed.
- `qgate baseline create` and `prune` use the working-tree `qgate.toml` when it
  differs from the staged one, report which config they used, and say why
  nothing was written.
- Duplicate prune hints say how many copies remain instead of "lost copies".
- Erlang's `Error:` and `Warning:` lines are recognised.
