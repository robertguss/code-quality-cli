## Upgrading from v0.3.0

Bump the pinned version in each repo, remove any `[approvals]` section, and
rewrite the agent skill:

```sh
$EDITOR qgate.toml                # qgate_version = "0.4.0"; delete [approvals]
qgate install                     # writes the new agent skill
git rm -r --ignore-unmatch .qgate # old signed approval records, if any
git add qgate.toml .claude/skills/qgate .agents/skills/qgate
git commit -m "Upgrade qgate to v0.4.0"
```

v0.4.0 measures code the same way as v0.3.0, so baselines don't need to be
recreated.

## Approvals are gone

- `qgate approve`, signed approval records (`.qgate/approvals/`) and the
  `[approvals] allowed_signers` setting are removed. A config that still has
  `[approvals]` fails to load until the section is deleted.
- Loosening the gate no longer blocks a commit or push. Raising a limit,
  growing the baseline, editing a tool's config, excluding files or adding an
  inline ignore is now a `loosening` warning in the run output, so you and the
  agent still see every place the gate got weaker. Repo tools always run.
- The Claude Code hook no longer blocks `qgate approve` or `ssh-keygen -Y sign`,
  and no longer protects `.qgate/`. It still blocks `--no-verify`, hook-skipping
  config and tampering with the hooks.
- The agent skill now tells agents to prefer fixing the code, and to tell the
  developer when they loosen the gate.
